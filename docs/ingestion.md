# 资料摄取与格式适配

## 1. 设计目标

资料摄取层负责把不同格式转换为统一的内容单元，同时保留原始文件、结构信息、媒体资源和可引用定位。格式适配器只负责提取内容，后续的清洗、分块、实体抽取、关系构建和检索使用统一接口。

## 2. 支持范围

### 文档和电子书

- PDF，包括文字型 PDF 和扫描型 PDF
- DOCX、ODT、RTF
- Markdown、TXT、HTML、XML、JSON、YAML
- EPUB 和其他常见电子书格式

### 演示文稿和表格

- PPTX、ODP
- XLSX、ODS、CSV、TSV

### 图像和扫描资料

- PNG、JPEG、TIFF、WebP
- 页面截图、扫描件和图版
- OCR 文本与版面区域

### 音频、视频和压缩包

- WAV、MP3、M4A 等音频
- MP4、MOV、WebM 等视频
- ZIP、TAR、7z 等压缩包中的可识别文件

音频和视频属于扩展能力。启用后，系统保存转写片段、时间点和关键帧，并将它们作为可引用证据。

## 3. 统一抽取接口

每个格式适配器输出统一的 `ContentUnit`：

```json
{
  "document_id": "doc:example",
  "unit_id": "doc:example:unit:12",
  "unit_type": "page|slide|sheet|section|time_range",
  "locator": {
    "page": 12,
    "slide": null,
    "sheet": null,
    "cell": null,
    "start": null,
    "end": null
  },
  "title": "章节标题",
  "text": "清洗后的文本",
  "blocks": [],
  "assets": [],
  "extraction": {
    "method": "native|ocr|asr|keyframe",
    "engine": "engine-name",
    "confidence": 0.91
  }
}
```

## 4. 格式适配策略

### 原生结构优先

对于 DOCX、PPTX、XLSX、HTML 和结构化文本，优先读取原生段落、标题、形状、表格、工作表和超链接。

### 版面和图像补充

对于 PDF、扫描件和图版，先提取页面图像，再进行 OCR、版面分析和图像区域裁剪。原始页面图像与 OCR 文本同时保存。

### 兜底转换

对于暂未实现专用适配器的格式，先根据 MIME 类型尝试通用转换器，再将转换结果标记为低置信度，并保留原始文件供人工复核。

### 压缩包递归处理

压缩包建立父子来源关系。系统记录压缩包内部路径、文件哈希和提取状态，避免不同压缩包中的同名文件混淆。

## 5. 文件版本和去重

每个来源文件保存：

```text
source_id
original_name
mime_type
file_size
sha256
created_at
updated_at
parent_archive
corpus_id
```

文件哈希用于去重和版本追踪。用户重新上传同一文件时复用已有抽取结果，文件内容变化时创建新的文档版本。

## 6. 资料加入后的流程

```text
上传或导入
  -> 文件识别
  -> 格式适配器提取
  -> 页面或内容单元生成
  -> OCR、ASR 或关键帧处理
  -> 文本清洗和分块
  -> 实体关系抽取
  -> 关键词、向量、图像索引
  -> 可检索和可引用
```

扫描 PDF 和图片采用按需 OCR。导入文件只保存原始资料和元数据，页面识别由 admin 手动启动。首次可以只处理前几页作为样例，再从已完成页继续或处理剩余页面。每批 OCR 结果立即写入数据库，进程中断后不会要求重新识别已经保存的页面。

OCR 提供快速和高质量两档。快速档使用较低的渲染分辨率和自动版面分析，高质量档使用更高分辨率和单块版面分析。低置信度页面进入发布前整体审核摘要。

## 7. 用户可见状态

公开应用中应展示每个语料库和文件的处理状态：

- 已发现
- 提取中
- 待人工校验
- 已建立索引
- 已加入知识图谱
- 处理异常

异常记录包含文件、处理阶段、错误信息和可重试操作。
