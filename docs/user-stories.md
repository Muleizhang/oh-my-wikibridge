# User Story Map

## 1. 产品愿景

作为知识工程课程的学习者或研究者，我希望把来自书籍、文档、演示文稿、表格、图片和其他媒体的资料加入同一个知识系统，使系统能够提取可追溯的知识、建立实体关系、回答自然语言问题，并通过关系图、时间轴、图像和报告展示分析结论。

系统使用用户本机的 OpenCode 作为默认 LLM 后端。知识库、检索、图谱、证据和可视化由本项目维护。

## 2. 用户角色

### user

只读用户，可以浏览已发布的语料库、搜索资料、提出 RAG 问题、查看工具调用、浏览图谱和导出结果。user 可以设置当前查询使用的语料库范围和筛选条件。

### admin

拥有完整权限，可以管理语料库和文件、运行处理流程、审核抽取结果、发布知识库、配置 OpenCode、处理异常和管理系统设置。

## 3. 端到端主流程

```text
admin
  -> 准备本机后端
  -> 创建语料库
  -> 添加多格式资料
  -> 解析、OCR 和建立索引
  -> 查看抽取结果和审核汇总
  -> 发布知识库版本

user
  -> 选择已发布语料库
  -> 搜索或提出问题
  -> 查看 RAG 工具调用
  -> 查看回答、引用、图谱和图像证据
  -> 分析关系和形成结论
  -> 导出结果并分享
```

## 4. User Story Map

### 4.1 准备系统

#### US-001 检查本机后端

作为 user，我希望系统自动检查 OpenCode 是否已安装、是否能够访问模型以及是否支持当前连接方式，以便我知道系统是否可以开始工作。

验收条件：

- 显示 OpenCode 是否存在和版本号
- 显示可用模型和模型能力
- 区分未安装、未配置、可用和连接异常
- 不把模型密钥写入项目日志

#### US-002 引导安装 OpenCode

作为 admin，当 OpenCode 不存在时，我希望看到适合当前系统的安装说明，并能在安装后重新检测，以便完成后端准备。

验收条件：

- 显示安装原因和官方安装入口
- 支持复制安装命令或打开安装页面
- 用户确认后才执行自动安装操作
- 安装结束后重新执行版本和模型检查

#### US-003 选择模型角色

作为 admin，我希望为信息抽取、RAG 回答和分析任务选择模型，以便根据任务难度和输入类型调整系统。

验收条件：

- 可以读取 OpenCode 当前可用模型
- 显示文本、图片、PDF 和工具调用能力
- 保存角色与模型的对应关系
- 每次回答记录实际使用的模型标识

### 4.2 管理语料库

#### US-004 浏览可用语料库

作为 user，我希望查看可用的主题语料库和简介，以便选择合适的资料范围。

验收条件：

- 显示语料库名称、说明和资料范围
- 显示语料库的发布状态和更新时间
- user 只能访问已发布内容
- 可以选择一个或多个语料库作为当前查询范围

#### US-005 创建主题语料库

作为 admin，我希望创建一个有名称、说明和主题标签的语料库，以便把不同项目的资料分开管理。

验收条件：

- 可以创建、重命名和归档语料库
- 语料库拥有稳定标识
- 检索和图谱查询可以限定语料库范围
- 不同语料库的结果不会自动混合

#### US-006 添加文件和媒体

作为 admin，我希望添加 PDF、DOCX、PPTX、XLSX、Markdown、HTML、TXT、CSV、图片和其他常见格式，以便使用已有资料开始构建知识库。

验收条件：

- 显示文件名、格式、大小、哈希和加入时间
- 同一文件重复添加时可以识别已有版本
- 保留原始文件和来源信息
- 支持批量添加多个文件

#### US-007 管理文件版本

作为 admin，我希望查看文件版本和处理记录，以便知道某条知识来自哪一版资料。

验收条件：

- 显示文件版本和哈希
- 新版本不会覆盖旧版本的证据
- 知识条目可以回到具体文件版本
- 能够重新处理指定版本

### 4.3 处理资料

#### US-008 查看解析状态

作为 admin，我希望看到每个文件处于发现、提取、OCR、分块、抽取、索引或异常状态，以便了解处理进度。

验收条件：

- 显示当前阶段和进度
- 显示已处理单元数量
- 失败时显示文件、阶段和错误信息
- 支持从失败阶段重试

#### US-009 获得统一内容单元

作为 admin，我希望不同格式都转换为页面、幻灯片、工作表、章节、段落、表格和媒体片段等统一内容单元，以便后续模块使用相同接口。

验收条件：

- 每个内容单元有稳定 ID
- 保留标题、正文、表格、图片和原始定位
- PDF 和图片支持 OCR
- 音频和视频可以扩展为转写片段和关键帧

#### US-010 回到原始证据

作为 user，我希望从任意公开结果回到原始页面、幻灯片、表格单元格或媒体时间点，以便检查内容是否被正确理解。

验收条件：

- 页面、幻灯片和工作表定位可显示
- OCR 文本和原始图像可以同时查看
- 图像区域可以在原始页面中定位
- 引用信息可以被 RAG 回答直接使用

### 4.4 校验结构化知识

#### US-011 查看实体和属性

作为 user，我希望查看系统识别出的实体、属性和来源，以便理解资料被转换成了哪些知识点。

验收条件：

- 显示实体类型、名称、别名和来源
- 显示抽取方式和置信度
- 可以打开证据文本或图像
- user 只看到已发布版本中的实体和属性

#### US-012 发布前批量审核

作为 admin，我希望在知识库对 user 开放前统一查看抽取结果、错误统计和代表性证据，以便完成一次整体审核后发布知识库。

验收条件：

- 自动抽取结果先处于草稿状态
- admin 可以查看实体、关系、来源和置信度汇总
- admin 可以批量发布、退回处理或修订明显错误
- 发布后形成可供 user 读取的知识库版本
- 保存审核者、时间、版本和审核结果

#### US-013 查询知识图谱

作为 user，我希望按实体、属性和关系查询已发布的知识图谱，以便发现文档中不容易直接看出的关联。

验收条件：

- 支持模板化查询和 SPARQL 查询
- 支持限定语料库、时代、地域和来源
- 结果可以导出为表格或图结构
- 结果可以跳转到证据页面

### 4.5 搜索和 RAG 问答

#### US-014 使用关键词检索

作为 user，我希望使用关键词、来源和属性筛选资料，以便快速定位相关内容。

验收条件：

- 支持全文、标题、图注和 OCR 文本检索
- 支持按语料库、格式、时期和文件筛选
- 返回匹配片段和来源定位
- 支持分页和结果排序

#### US-015 使用语义检索

作为 user，我希望使用自然语言描述一个概念，即使没有使用原文词语，也能找到相关内容。

验收条件：

- 支持 Word2Vec 或文本向量检索
- 返回相似度和匹配片段
- 可以查看关键词检索与语义检索的差异
- 检索结果保留来源信息

#### US-016 提出 RAG 问题

作为 user，我希望用自然语言提问，并得到基于我选择的语料库范围的回答，以便快速理解资料内容。

验收条件：

- 可以选择一个或多个语料库和过滤条件
- OpenCode 能够调用检索、图谱和证据工具
- 回答附带卷册、页码、段落、幻灯片或时间点
- 回答区分原文事实和分析推断

#### US-017 查看 RAG 过程

作为 user，我希望查看回答使用了哪些检索结果、图谱关系和证据，以便理解 RAG 的工作过程。

验收条件：

- 展示工具调用记录和检索路径
- 显示引用片段和实体关系
- 可以展开查看原始页面和图像
- 可以重新运行同一问题

#### US-018 进行图像检索

作为 user，我希望上传图像或选择一个纹样，找到视觉上或语义上相近的图版，以便比较纹样变体。

验收条件：

- 支持图像向量检索或纹样实体检索
- 结果显示相似图像、文本说明和来源
- 可以按时代、材质和器物筛选
- 图像结果可以进入 RAG 上下文

### 4.6 分析和可视化

#### US-019 浏览关系图

作为 user，我希望查看实体、关系和证据组成的图谱，以便理解知识之间的结构。

验收条件：

- 节点和边显示名称、类型和关系
- 点击节点可以查看属性和证据
- 支持按关系类型和来源过滤
- 支持导出 PNG、GraphML 或 JSON

#### US-020 浏览时间轴

作为 user，我希望按历史时期浏览实体和纹样关系，以便分析演变和延续。

验收条件：

- 时间轴显示卷册和历史时期
- 事件或实体可以打开来源页面
- 支持按题材、材质和器物筛选
- 可以比较两个时期的分布

#### US-021 查看统计和降维结果

作为 user，我希望查看词语共现、TF-IDF、SVD 或 PCA 结果，以便理解不同表示方法发现的关系。

验收条件：

- 显示统计口径和数据范围
- 图表可以回到样本或来源
- 可以比较不同语料库和时期
- 结论标明是统计结果还是人工解释

#### US-022 形成可引用结论

作为 user，我希望将关系图、统计结果和 RAG 证据组合成结论，以便写入实验报告或向小组成员展示。

验收条件：

- 每条结论保留使用的数据和证据
- 可以区分直接证据、图谱推理和统计推断
- 可以导出 Markdown、HTML 或报告数据
- 结论可重新运行和复核

### 4.7 协作和导出

#### US-023 导出知识资产

作为 user，我希望导出公开的结构化数据、图谱、检索结果和引用清单，以便在其他工具中继续工作。

验收条件：

- 支持 CSV、JSONL、JSON-LD、RDF、GraphML 和 Markdown
- 导出文件包含来源定位和版本信息
- 导出结果不包含模型密钥
- 能够重新导入结构化知识

#### US-024 分享分析结果

作为 user，我希望分享一个问题、回答、关系图或证据集合，以便其他成员复核同一结果。

验收条件：

- 分享对象包含语料库、文件版本和运行参数
- 其他成员可以看到引用和图谱状态
- 结果页面不会依赖个人本机的临时路径
- 可以标注结果的生成时间和模型版本

## 5. MVP 范围

第一版优先完成以下用户价值链：

```text
检测 OpenCode
  -> 创建语料库
  -> 添加 PDF、DOCX、PPTX、XLSX、TXT 或 Markdown
  -> 提取文本和定位信息
  -> 建立关键词与向量索引
  -> 进行带引用的 RAG 问答
  -> 查看基础实体关系图
  -> 导出回答和证据
```

三册纹样资料作为初始数据集参与第一版演示。其他格式、图像向量、音频视频和高级协作功能逐步加入。

## 6. 版本优先级

### Must have

- OpenCode 检测、安装引导和模型状态
- 语料库浏览、创建和文件添加
- 多格式文本提取
- 来源定位和证据查看
- admin 发布前整体审核
- 基础关键词与向量检索
- RAG 问答和引用
- RAG 工具调用过程展示
- 基础实体关系图

### Should have

- 实体关系审核
- 图谱查询
- 图像相似检索
- 时间轴和统计分析
- 课堂方法对照实验
- Markdown、HTML 和 GraphML 导出

### Could have

- 音频、视频和关键帧
- 多人协作审核
- 自动生成研究报告
- 更复杂的跨语料库推理

| 使用词语相似度检索 | HW2 |

## 8. 信息来源与排序规则

项目暂不建立面向用户的知识权威等级或来源优先级。系统保存来源文件、版本、页面定位、证据片段、抽取方法和置信度。

检索分数只用于排序，不能被解释为事实可信度。管理员发布前进行整体审核，user 读取已发布版本。需要比较不同来源时，展示各来源证据和版本信息，由 user 或研究者进行判断。
